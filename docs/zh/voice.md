# DiceFrame 语音功能（可选）

中文 | [English](../en/voice.md)

语音不是开团必填项。本页介绍语音朗读（TTS）、语音输入（ASR）、音色配置和常见排障。DiceFrame 只负责连接、播放和保存配置；Kokoro、GPT-SoVITS 等本地程序负责生成声音。

## 语音朗读（TTS）

### 先用浏览器音色

这是最省事的方式，不需要下载模型：

1. 打开 **管理 → 设置 → 模型配置**，语音模型选择“浏览器 / 系统音色”。
2. 打开 **管理 → 设置 → 高级参数 → 语音朗读**。
3. 按需打开“新 GM 叙事自动朗读”，保存即可。

实际音色由当前手机或电脑的浏览器和操作系统决定。关闭自动朗读后，游玩页仍可手动播放公开叙事。

### 使用 Kokoro

已经安装 Docker Desktop 的电脑可以先启动开源的 Kokoro-FastAPI CPU 服务：

```powershell
docker run --name diceframe-kokoro -p 8880:8880 ghcr.io/remsky/kokoro-fastapi-cpu:v0.6.0
```

第一次运行需要下载镜像和模型，完成后保持服务运行。然后在 DiceFrame 中：

1. 打开 **管理 → 设置 → 模型接口**，添加该服务商，Base URL 填 `http://127.0.0.1:8880/v1`，API Key 留空，并加入模型 `kokoro`。
2. 打开 **管理 → 设置 → 模型配置**，语音模型选择这个服务商和 `kokoro`。
3. 在插件商店或“本地安装”中安装并启用 **Kokoro 中文音色预设**；音色预设不是必需的，也可以在“我的音色”里直接填写服务已有的 Voice ID，例如 `zf_xiaobei`。
4. 回到 **管理 → 设置 → 高级参数 → 语音朗读**，在“角色音色分配”中选择默认、GM 和玩家音色，点击“保存并试听”。
5. 试听正常后，再决定是否打开自动朗读。

如果 DiceFrame 运行在 Docker 中，`127.0.0.1` 指向 DiceFrame 容器而不是宿主机；通常改用 `http://host.docker.internal:8880/v1`，或使用两个容器所在网络中的服务名。

### 使用 GPT-SoVITS

先按 GPT-SoVITS 自己的说明启动 HTTP API，再在 **管理 → 设置 → 模型配置** 选择 GPT-SoVITS 并填写服务商信息。每个个人音色还需要参考 WAV、与音频逐字对应的提示文本和语言：

- TTS 服务与 DiceFrame 在同一台机器、能读取同一文件时，可以直接上传 WAV。
- TTS 服务在另一台机器或另一个容器时，填写“TTS 服务端可见路径”；该路径必须能从 TTS 服务一侧读取。

### TTS 常见问题

- **连接失败**：先在浏览器打开 Kokoro 的 `http://127.0.0.1:8880/docs`，确认服务已启动，再检查 Base URL 是否带 `/v1`。
- **找不到音色**：确认音色预设已安装且启用，或检查 Voice ID 是否真实存在于当前 TTS 服务。
- **浏览器能播，本地服务不能播**：通常是 TTS 服务、端口或容器网络问题；切回浏览器音色不会影响游戏。
- 远程 TTS 会收到要朗读的公开叙事文本。介意隐私时优先使用本机服务，不要把管理接口或本地 TTS 端口直接暴露到公网。

## 语音输入（ASR）

语音输入会把行动输入框中的录音转换为文字。它需要浏览器麦克风权限，并且页面应通过 HTTPS 或 `localhost` 打开。

1. 在 **管理 → 设置 → 模型配置** 的“语音识别模型”卡片中选择“OpenAI 兼容”，再选择已保存的服务商和模型。
2. 在 **管理 → 设置 → 高级参数 → 语音识别** 设置超时并保存。
3. 点击“保存并录音测试”确认接口可用；游玩时点击行动输入框旁的麦克风按钮，录音结束后识别文字会填回输入框。

接口需要兼容 OpenAI 的 `/v1/audio/transcriptions`，常见模型包括 `whisper-1` 和 `SenseVoice`。不使用时选择“关闭”，页面会隐藏麦克风按钮。
